Loopra

持续推理 · 调用工具 · 保留会话 · Web 与桌面工作台

Loopra 把一次编码任务收成一条循环：阅读项目，调用受控工具，把结果收回来再推理，直到完成，或停在需要你决定的地方。 新建会话默认使用 Loopra Native，也可以改接 Claude Code、Codex、Pi 或 DeepSeek Harness。 Web 与桌面打开同一套界面，配置和会话与 Loopra 共用 ~/.loopra。

Agent 引擎

一个工作台，选择适合任务的 Agent

新建会话时选择引擎。Loopra Native 在本进程里推理和调用工具；外部引擎由本进程以 ACP 客户端驱动本机适配器，需要在后端所在机器安装依赖并完成认证。

引擎配置与能力范围接入文档

外部引擎的能力取决于各自适配器。GET /api/agent-engines 会报告每个引擎是否可用。Native 的模型渠道和审批不会自动覆盖外部引擎。需求执行和定时任务走 Native。也可以用 loopra acp 把 Loopra 自己提供给外部编辑器。
快速开始

三步上手

命令行和桌面端分开安装。下面三步用于 Loopra Native。外部引擎请先在后端所在机器完成安装与认证。

1

安装

安装包在 Releases。命令行装到 ~/.loopra/bin（Windows 为 %LOCALAPPDATA%\Loopra\bin），macOS 桌面端解压到 ~/Applications/Loopra.app。配置和会话在 ~/.loopra，已有 Loopra 数据可以直接接着用。

命令行 
irm https://raw.githubusercontent.com/ezdemo/loopra-release/main/.release/setup.ps1 | iex
桌面端 
irm https://raw.githubusercontent.com/ezdemo/loopra-release/main/.release/setup-gui.ps1 | iex
命令行 
curl -fsSL https://raw.githubusercontent.com/ezdemo/loopra-release/main/.release/setup.sh | bash
桌面端 
curl -fsSL https://raw.githubusercontent.com/ezdemo/loopra-release/main/.release/setup-gui.sh | bash

安装命令与下载区共用所选源：镜像通过 LOOPRA_MIRROR 传给官方脚本。所有 setup.ps1 / setup.sh 及 -mirror、-gui 变体均支持该变量；未设置时，标准脚本走 GitHub 直连，-mirror 脚本默认使用 gh-proxy.org。

2

启动服务

loopra 与 loopra web 相同。省略端口或写成 0 时，由系统分配空闲端口。打开控制台打印的访问地址；页面上的 API 请求携带 X-Loopra-Key。未设置 LOOPRA_ACCESS_KEY 时，每次重启都会更换密钥。桌面端打开同一套工作台，地址里带好密钥。loopra acp 只在标准输入输出上提供 ACP，不启动网页。

loopra
loopra web 4567
loopra acp
3

配置模型渠道

使用 Loopra Native 时，在设置页维护模型渠道并保存；也可编辑 ~/.loopra/config.json 后重启服务。每个渠道独立配置 API 地址、密钥、协议和模型能力，示例中的密钥与项目路径需要替换。外部 Agent 沿用自己的登录与模型配置。

{
  "model": "deepseek-v4-flash",
  "modelChannelId": "default",
  "modelChannels": [
    {
      "id": "default",
      "name": "Default",
      "baseUrl": "https://api.deepseek.com/v1",
      "apiKey": "sk-your-api-key",
      "apiProtocol": "chat_completions",
      "specialCompatibility": "",
      "models": [
        {
          "name": "deepseek-v4-flash",
          "contextTokens": -1,
          "maxTokens": 32768,
          "imageInput": false
        }
      ]
    }
  ],
  "workspaceDir": "/path/to/your/project"
}
安装与更新支持 GitHub 直连和镜像源，可通过 LOOPRA_MIRROR 指定镜像。Native 的 apiProtocol 支持 chat_completions、responses 和 anthropic，可选 OpenCode 兼容模式。maxTokens 是单次请求最大输出 token 数，包含推理 token。
核心能力

为真实开发场景设计的完整能力

以下内置工具、模型渠道、子代理和审批规则主要面向 Loopra Native；外部引擎能力以各自 ACP 适配器为准。

自主推理循环

流式输出推理、工具调用和结果，持续处理多轮任务。

上下文管理

JSONL 会话持久化、自动折叠、会话级模型和 token 用量统计。

多模型渠道

Chat Completions、Responses、Anthropic Messages 和 OpenCode 兼容网关。每个渠道分开配置地址、密钥、协议和模型能力。会话可以单独选择模型和推理强度。

可扩展工具系统

内置文件、rg、命令、联网、技能和 MCP。工具可启用或禁用，自定义工具可标成只读或写入。rg 随程序提供，不必另行安装 ripgrep。

代码库操作

在项目边界内读取、搜索、编辑文件，运行一次性或交互式命令。

子代理协作

默认提供 explore、implement、test、review、plan 五种角色，拥有独立上下文、工具范围和超时控制；可在设置中调整角色与渠道模型。

计划模式

输入框一键进入只读探索，探索完成后提交计划供用户审查，批准后按计划执行。

持久协作状态

Checklist、会话级 Goal、项目记忆和共享上下文支持长任务及父子代理协作。

审批与权限控制

free 跳过审批链，工具自身的路径与参数校验仍然生效。approval 放行只读、项目内写入和可识别的项目内命令。auto 再交给校验模型，拦下的调用转人工。

桌面工作台

React、TypeScript 与 NextUI 工作台负责项目、会话、聊天、模型和 Git。桌面端用原生窗口打开同一套页面。

隔离分支与项目环境

会话可以换到独立工作树里执行。Git 面板查看分支和差异，并负责提交与环境信息。

需求池与定时执行

看板管理需求，支持 AI 自动执行、评论、执行日志及立即／定时执行，并按需求配置模型和审批模式；使用 Native 执行链。

纯聊天与联网查询

选择「纯聊天」后不暴露项目、文件、终端或 Git 能力，仅启用联网查询类工具；会话仍独立持久化。

审批发生在应用层，工具自身的路径与参数校验仍然生效，它不替代操作系统沙箱。文件、命令和 Git 都发生在运行后端的那台机器上。
工具系统

内置工具

在工具管理里启用或禁用，自定义工具可以指定只读或写入。项目内检索统一走内置 rg。

分类覆盖场景
文件与代码检索 read、write、edit、rg
命令与网络 当前系统 shell 及其 _start / _wait / _stdin / _stop；web 的 search、code、fetch
任务协作 sub_agent、submit_plan、ask_choice；需求会话另有 finish_requirement、reply_requirement_comment、show_requirements
技能 skillread、skilllist、skillsearch、skillrefresh
外部工具 tool_search、call_tool 发现并调用 MCP 工具
技能来自内置 SelfSkill、用户目录 ~/.loopra/skills、通用目录 ~/.agents/skills 和项目目录 .loopra/skills。用户级 MCP 在 ~/.loopra/mcp-servers.json，项目级 MCP 只对当前项目生效。原生 Agent 通过固定的 tool_search 和 call_tool 使用它们。

技能

内置 SelfSkill 介绍能力入口和排查方式。同名技能用完整标识区分。目录可以在启动后创建，调用 skillrefresh 即可发现。技能市场安装到 ~/.loopra/skills。Java 插件和拓展包由可选的兼容后端执行。

对外发布工具

可将启用的工具通过 MCP Server 发布，默认关闭，支持 Streamable HTTP 或 SSE。可选 Cloudflare Quick Tunnel 仅代理 MCP endpoint；Quick Tunnel 需安装 cloudflared，并使用 Streamable HTTP。接口访问需要 X-Loopra-Key。

架构

一个入口，同一套工作台

工作台通过 HTTP / SSE 进入。Loopra Native 在本进程里完成推理和工具调用；外部引擎由本进程以 ACP 客户端驱动。loopra acp 则把 Loopra 提供给外部编辑器。

入口

cmd/looprax

Web、桌面和 ACP 的启动入口。不写子命令时启动工作台，loopra acp 只占用标准输入输出。

应用

internal

智能体、工具、审批、会话、MCP 和需求。依赖集中注册，业务代码不查全局容器。

工作台

web

React、TypeScript 与 NextUI。桌面端用原生窗口打开同一套页面，文件和命令发生在后端所在机器。

文档

intro / docs

官网与项目文档随仓库一起维护。配置和 JSONL 会话放在 ~/.loopra。

Web / 桌面 → HTTP / SSE → Loopra Native → 工具、技能、MCP
                         → 外部 Agent
外部编辑器 → loopra acp → Loopra Native
  • 改界面从 web/ 进入，改能力从 internal/ 和 adk/ 进入。
  • 配置和会话在 ~/.loopra，与 Loopra 共用。Java 插件和拓展包由可选的兼容后端执行。
  • 装配、配置加载和请求链路见架构指南。安装包在 loopra-release。
