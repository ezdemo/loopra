# 半异步工具执行

半异步是服务端声明的执行能力，不按工具名判断。原生工具通过 `tools.Metadata.Async` 声明，插件通过 `tools()` 条目的 `async: true` 声明；注册表统一包装执行。当前启用一次性 shell、`rg`、`sub_agent` 和内置 `web`。未声明的工具保持同步，原生主会话（Web、桌面与 Loopra ACP 服务端）提供执行运行时；外部 ACP 引擎不受此机制控制。

`yield_after_ms` 是包装器保留参数：注册时注入模型参数定义，执行前校验并剥离，再把原业务参数交给工具。业务 schema 不应重复声明它。`/api/tools` 返回 `async` 能力及包含此参数的 `params`，不增加用户配置项。声明本身不改变读写分类或审批；审批在包装器之外完成，插件 `toolBefore` 仍先执行，`toolAfter` 仅处理真实最终结果一次。

子代理调用可让出父循环，但子代理内部 Runner 不继承父队列，内部工具仍同步执行。MCP 导出没有轮次运行时，包装器消费通用参数后同步执行。异步子代理产生的文件变更随最终结果持久化，父会话历史仍可恢复这些变更。

## 调用与获取结果

- `yield_after_ms`：同步等待窗口，默认 5000，0 使用默认值，最大 60000 毫秒。窗口内结束直接返回原结果；到期返回 `{async:true,status:"running",call_id,message}`，原操作继续执行。
- `timeout_ms`：原工具的执行期限，含同步等待时间，维持原默认值、上限与进程树清理语义。让出循环不会重置执行期限。
- `tool_result`：参数 `{call_id,timeout_ms?}`；等待默认 1000、最大 60000 毫秒，0 使用默认值。只能读取当前轮次的后台调用；未知、其他会话或旧轮次 ID 返回错误。
- 主动查询尚未完成时返回 `running`，不取消自动交付。取得最终结果后返回 `{call_id,name,status,result,error?}` 并消费交付权；重复查询返回 `status:"delivered"`，提示在上下文中查看已交付的结果。
- 自动交付与主动查询共享同步边界，只有一条路径交付最终结果。原调用执行一次，不能因为返回 `running` 就重新执行。存在依赖的后续操作应先等待结果。

## Loop 与生命周期

执行记录由当前用户轮次拥有，审批暂停和恢复复用同一运行时。后台工具继承调用上下文的值，但取消和期限绑定用户轮次，避免 ADK 的单次模型调用结束就取消工具。

工具完成后立即通知现有结果接收端；下一次模型请求前持久化结果，并将尚未交付的结果作为带调用 ID 的工具完成通知加入上下文。正在流式生成的请求不被修改。模型暂时给出文本结束时，若仍有未交付结果，外层循环等待完成信号后继续，不忙轮询，也不发出提前的 `complete` / `done`。

原始调用的 `FunctionResponse` 只返回一次。晚到结果的模型视图是单独的 user-role 工具完成通知，正文明确标记为工具输出，不是假装用户发来的新指令，也不是重复的相同 ID 工具响应。主动查询已经交付的结果仅记录元数据，不再次注入正文。

退出、取消或消费者提前停止后，运行时先取消并等待所属执行清理，再释放资源。取消后的最终结果仍写入历史。显式交互/结束工具保留暂停或结束语义；停止整个轮次时取消尚未完成的后台执行。外部工具接入前必须保证遵守 context 取消、不修改 ADK 事件动作，并单独验证审批和资源释放。

运行时不跨进程重启恢复：已写入的结果可重新加载，强制退出时仍运行的记录可能只保留 `running` 回执，不应视为执行成功或自动重试有副作用的操作。

## SSE 与 JSONL

SSE 不增加新事件。原调用照常发送 `tool_call`，异步回执不发送终态 `tool_result`；真实完成后按原 `toolCallId` 发送一次 `tool_result`。查询工具自己的结果是独立工具响应，即使查到 `running`，该次查询本身也已完成。`complete` / `done` 等待循环实际结束。

JSONL 保持追加写入，`.events` 不改写。异步回执的原工具行增加 `tool_status:"running"`。晚到结果追加 `role:"tool"` 行，包含原 `tool_call_id`、`tool_name`、`content`、`tool_status:"completed"|"failed"` 与 `async_tool_result:true`；`adk_event` 保存实际的通知事件或仅元数据事件。模型历史通过 `adk_event` 恢复，前端按调用 ID 取最后一条结果更新原条目。旧数据没有这些字段时维持原解析方式。

`read_tool_result(callId)` 仍用于读取持久化原始结果，按既有隔离规则优先读取晚到的最终结果，支持分页；它与仅查询当前轮次执行状态的 `tool_result(call_id, timeout_ms)` 不同。

结果持久化失败向调用方报告错误，失败的记录不标记为已保存。正常关闭期间取消结果也会尝试持久化；无法保存时记录错误。历史中的 `running` 仅表示尚无最终记录，不证明重启后仍有进程执行。
